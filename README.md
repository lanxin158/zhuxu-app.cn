# 筑序 · 施工效率驾驶舱（正式演示版）

面向项目经理、生产经理和现场管理人员的施工全过程效率管理系统。一套局域网服务器可管理多个项目，每个项目拥有独立的组织架构、账号授权与业务数据；支持新项目首次启动初始化。

## 当前能力

- 一套服务器可建立多个项目：每个项目独立登录、独立组织架构与数据空间，项目间互不可见；登录时选择项目。
- 同一登录账号可参与多个项目：由各项目项目经理将账号加入对应项目后，登录任意一个项目即可在顶栏项目菜单中一键切换到其他项目，无需重复注册或重新输入密码；未获授权的项目不会出现在列表中。
- 建立新项目时，管理员账号可以填**已有账号**（复用该账号作为新项目经理，使用其原密码登录）或新建账号；创建者自动成为新项目成员，建完即可在顶栏菜单切换进入。
- 新项目首次启动（全新数据库）自动进入“初始化向导”：建立项目并登记第一位管理员（项目经理），管理员账号密码由创建者设定。
- 项目经理可随时在项目菜单中建立新的项目系统，并指定新项目的管理员账号。
- 提供独立登录页、登录会话、保持登录和安全退出；账号与组织架构人员、岗位权限绑定，且只能在被授权的项目登录。
- 局域网多人版首次登录必须修改初始密码，新密码至少 8 位且同时包含字母和数字；改密后该账号的其他登录会话自动失效。
- 项目经理在组织架构中新增人员即自动生成登录账号：账号唯一、初始密码为登记手机号后六位、首次登录强制改密；组织架构页可维护账号（新增、编辑、禁用/启用与重置密码）。
- 服务端授权：未改密的账号不能写任何共享数据；组织架构数据仅项目经理可写入，实名制考勤仅劳资员或项目经理可写入，越权请求被拦截并写入审计记录。
- 新项目从零开始，不含演示组织与演示业务数据；离线演示版保留“云河智造中心一期”示例数据用于体验。
- 材料审批只允许当前节点指定本人操作，其他账号可查看进度但不能代办；审批操作记录账号和时间。
- 登录后直接进入“每日任务执行中心”，不再设置独立总览入口；组织架构在专门页面维护，以账号职位作为责任匹配依据。
- 进度计划分为总计划、月计划、周计划、日计划：总、月、周计划均以已批准的网络图或横道图原文件为准，上传后直接在大窗口显示，不再在系统内重复编制。
- 月计划页面以 12 个月份按钮切换；周计划按自然周（周一至周日，可有4—6周）展示原文件及目标清单。原四周周期上传文件保留原日期，展示在“原周期计划文件”中，不迁移覆盖。
- 日计划按执行日期归档，列出施工内容、计划目标、责任人和班组；统一从侧栏“每日例会”批量编制次日计划，进度计划页只查看，不再提供重复例会编辑入口。
- 任务模块支持 Excel、Word、PDF、图片、CSV、TXT 和语音识别，识别结果写入前可人工校核。
- 任务支持手工录入、文件识别和语音转文字；系统按任务内容匹配岗位与责任人，且可人工修正。
- 每日任务执行中心按所选日期展示日计划及昨日未完成项目；实际完成率只采用例会确认结果，未确认显示“待例会确认”，不再把系统默认或普通施工反馈算作实际完成。
- 每日例会单项确认当天计划的实际完成率（100% 表示完成当天计划全部内容），确认后即时同步今日跟踪并锁定。支持选择历史日期补确认，但已确认结果不能修改；明日计划、协调事项仍在此批量编制并同步。
- 计划目标与实际完成率独立记录，例如计划80%、实际100%表示该80%全部完成；计划80%、实际50%折合40%。普通施工记录仍可补充备注和照片，但不能改动已确认的完成率。
- 右上角待办标识可展开具体事项；项目经理、技术负责人、生产经理查看本项目全部待办，其他人员只看分配给自己的待办。窄屏也显示入口。
- 计划跟踪中“班组人员”可点开查看该日班组人员的姓名、工种、上下班打卡时间（来自劳资员上传的实名制考勤，Excel 打卡表自动提取姓名/工种/打卡时间）；技术交底也可点开查看；“材料保障”并入需协调事项、“资料门禁”并入资料风险项，不再重复展示。
- 资料风险项与资料完成情况均标注具体部位（如“钢筋复试报告 · 3#楼 8F 梁板钢筋绑扎”）。
- 本周每日投入人数只读取劳资员上传的实名制打卡记录；没有考勤记录的日期明确显示“未上传”，不使用任务填报人数替代。
- 班组可提前提交需协调问题，系统持续展示提出人、责任人、最晚解决时间以及“待跟进—正在跟进—已完成”的闭环状态。
- 任务中的设计变更和施工指令带明显风险标识；弹窗直接展示技术内容、适用范围和上传原文件，并保存接收对象、确认人和确认时间。
- 侧边栏“技术文件”统一共享施工图纸、设计变更、联系函和指令单，支持按标题、编号、专业、部位和附件名查找；非图纸文件可查看正文、编辑信息、删除附件或重新上传，并可与每日任务中的技术交底关联。
- 施工图按“单体 / 专业 / 图纸”三级文件夹归档（也可手动“新建单体”）；上传整个图纸文件夹时自动识别“3#楼结构”等根目录的单体和专业，打开专业子文件夹后点击图纸直接交给浏览器或系统适合的软件打开，不再经过详情弹窗。
- 左侧天气卡为项目晴雨表入口，可切换查看全年 12 个月历史天气；计划开工、实际开工、基础验收、主体验收、封顶等重要事件以不同颜色标注，点击节点查看说明。
- 侧边栏新增“成控文件”，统一管理合同、经济核定单和现场工程量确认单，记录责任单位、涉及金额、工程部位、确认内容及签章原件。
- 成控文件仅项目经理及商务、成本、造价岗位可进入；局域网服务端同时限制成控数据读取、写入和附件下载，并记录越权拦截审计。
- 材料和资料保障卡只显示未闭环风险项；复试、检测报告、门禁等阻断项红色警示，普通待签字资料提示“待完善”。
- 原始信息采集继续支持文件、表格、照片、语音和手工记录，人工校核后可分发到现有业务台账。
- 所有任务均可编辑，也可按紧急或一般级别催办影响本任务的前置工序。
- 现场记录支持拍照或从相册选择多张照片，压缩后持久保存到浏览器本地数据库。
- 材料和设备分开管理，并分别登记名称、分类、品牌、规格、进出场时间、数量、使用部位和附件。
- 材料与设备进场登记支持批量录入：可在同一弹窗一次添加多条记录，逐条填写并关联计划、上传附件；保存后仍按独立台账行显示，分别累计到场数量并生成对应资料待办。
- 材料按类别汇总；合格证、见证取样和验收照片可随进场记录保存。
- 材料进场后自动通知资料员，并生成“是否取样送检、是否留存合格证”的待办事项。
- 材料与设备计划可单独新建，记录需求日期、数量、责任岗位和状态。
- 材料设备计划责任岗位从项目组织架构读取，覆盖施工员、质量员、材料员、试验员等岗位。
- 材料设备计划在要求到场前 7 天自动进入预报，临近或逾期未到场时分级提示。
- 材料设备计划详情展示逐级审批进度；提报人、上一位已通过的审批人以及项目经理可催办当前待审批节点，催办通知会进入当前审批人的站内提醒并在审批完成后自动闭环。
- 材料计划提报人点击提交即视为已完成提报节点，审批从生产经理开始，不再要求提报人重复审批；提报人仍保留在流程中作为发起记录。
- 台账登记可自动推荐或人工指定关联计划；分批到场会累计已到数量，并实时计算剩余数量。
- 材料、设备台账及计划清单均可点击查看完整详情和关联到场记录。
- 材料设备附件原文件保存到浏览器附件库；图片可直接预览，PDF可在线打开，其他文件可下载查看。
- 资料完成情况与施工进度关联，覆盖钢筋、混凝土和防水工程资料链及工序放行。
- 所有材料进场批次都会生成对应资料链，自动带入品牌、规格、数量和使用部位。
- 资料任务可查看编辑，分别保存送检委托和检测报告，并记录待送检、检测中、合格或不合格状态。
- 质量与安全检查支持编辑、巡检表上传、整改前后照片和复验闭环，统计卡片可展开具体内容。
- 组织架构页记录项目管理人员姓名、职务、管理范围及电话；现场人数由劳资员上传每日实名制考勤表更新。
- 全局“记录施工反馈”只在每日任务执行首页显示，其他页面保留各自的业务操作入口。
- 二级页面提供固定返回按钮，适配桌面、平板和手机屏幕。
- 支持晨会简报、效率建议和项目 JSON 数据导出。

## 文件识别说明

- DOCX、XLSX、CSV、TXT：在浏览器本地解析，可形成多条可编辑任务。
- PDF：当前原型使用本地文本特征提取，复杂排版或扫描件需要人工校对。
- 图片：浏览器支持原生文字检测时会直接识别；不支持时生成待校对候选项。
- 语音：浏览器支持语音识别且授予麦克风权限时可直接转文字，也可粘贴转写稿后解析。

生产环境若要求稳定识别扫描 PDF、施工计划照片和嘈杂现场语音，建议接入企业 OCR、语音识别及大模型结构化服务。

## 运行方式

### 项目局域网多人试用（推荐）

1. 在作为项目服务器的电脑上双击 `启动局域网版.cmd`。
2. Windows 防火墙首次询问时，允许 Node.js 访问“专用网络”。
3. 启动窗口会显示本机和局域网登录地址。
4. 本机访问 `http://127.0.0.1:8080`；同一 Wi-Fi/局域网中的其他设备访问 `http://服务器电脑IP:8080`。
5. 当前电脑的 WLAN 地址示例为 `http://192.168.1.6:8080`，地址变化时以启动窗口显示为准。

多人版数据保存在 `data/zhuxu-lan.sqlite`，请定期备份该文件。关闭启动窗口或按 `Ctrl+C` 会停止服务，作为服务器的电脑需要保持开机和联网。

多人版支持一套服务器管理多个项目：首次启动（全新数据库）进入“初始化向导”建立第一个项目和管理员；之后项目经理可在顶栏项目菜单中建立更多项目。每个项目的每日执行反馈、协调事项、原始信息采集、技术文件、成控文件、任务、计划、材料设备台账、资料状态、审批流程、质量安全、组织架构和考勤数据完全隔离；服务器同时校验登录会话、项目授权、首次登录改密、材料审批权限、成控文件岗位权限以及组织架构/考勤写入权限，上传附件由服务器统一保存并可跨设备查看。

### 本机离线演示

直接使用浏览器打开 `index.html`，无需启动服务。该模式的数据只保存在当前浏览器中，不与其他人同步。

若只需临时静态预览，可在此目录启动静态文件服务：

```powershell
python -m http.server 8080
```

然后访问 `http://localhost:8080`。

## 开发基线

### 环境要求

- Windows 10/11；
- Node.js 24 或更高版本（服务端使用内置 `node:sqlite`）；
- npm；
- Google Chrome，默认安装位置为 `C:\Program Files\Google\Chrome\Application\chrome.exe`。

首次获取代码后安装锁定版本的开发依赖：

```powershell
npm ci
```

启动局域网服务：

```powershell
npm start
```

运行完整开发基线检查：

```powershell
npm test
```

完整检查包含 JavaScript 语法、桌面和移动端离线流程、材料审批与隐蔽验收、信息采集与业务分发，以及局域网多账号登录、共享状态和服务端审批权限。局域网测试会自动创建并清理独立的临时数据库，不会改动 `data/zhuxu-lan.sqlite`。

测试生成的 `qa-*.png` 截图、`node_modules/`、npm 缓存、运行数据库和上传附件均已加入 `.gitignore`。切换 ChatGPT、Codex 或 DeepSeek 前，应更新 [HANDOFF.md](HANDOFF.md)，并只交接项目文件、普通文本和稳定 JSON，不传递供应商原始响应对象。

## 登录说明

- 局域网多人版支持多个项目，登录前先在“登录项目”下拉中选择要进入的项目。
- 新项目首次启动（全新数据库）不显示登录页，而是显示“初始化向导”：填写项目名称、项目编码和管理员（项目经理）信息，管理员密码由创建者自行设定。
- 项目经理登录后，在“组织架构 → 账号管理”中新增人员即自动生成登录账号：账号由创建者指定且全局唯一，初始密码为该人员登记手机号的后六位。
- 局域网多人版首次登录会强制修改初始密码：新密码至少 8 位且同时包含字母和数字；修改成功后旧密码失效。
- 账号的新增、编辑、禁用/启用和重置密码由项目经理在“组织架构”页的账号管理中完成；重置后该账号恢复为初始密码并需再次改密。
- 只有被项目经理加入当前项目组织架构的账号才能登录该项目，其他账号即使密码正确也会被拒绝。
- 同一账号被多个项目授权后，登录其中任意一个项目，点击顶栏“当前项目”即可在授权项目间一键切换，无需重复登录；切换后进入对应项目的独立数据空间。
- 建立新的项目系统时，“管理员账号”可直接填已有账号（如本人账号）：系统复用该账号作为新项目经理（使用原密码登录），并把创建者加入新项目；也可填全新账号（此时需设置初始密码）。
- 所有密码输入框（登录、初始化、新建项目、修改密码）均提供“显示/隐藏”按钮，方便核对输入。
- 左侧栏底部可退出当前账号；退出后必须重新输入账号和密码登录。

离线演示版（直接打开 `index.html`）保留“云河智造中心一期”示例账号与数据用于体验，密码校验与数据保存在浏览器本机，不强制改密、不支持多项目。局域网多人版已由服务端完成密码哈希（scrypt 加盐）、会话管理、项目授权、首次登录改密、账号管理与岗位权限校验，并记录审计留痕。

## 材料到场资料闭环

- 材料进场登记支持批量录入，保存后按日期倒序分组，每条材料独立显示并可打开详情。
- 每条材料进场记录必须上传收货单和到场/验收照片；合格证、检测报告等资料可选上传。
- 登记后自动生成资料员核查待办。资料员可确认“否，资料齐全”或“是，有缺失资料”，缺失内容会反馈给材料员和责任工长并显示风险。
- “资料完成情况”提供到场材料核查清单，个人提醒可直接打开对应材料详情。补充资料追加回材料台账，已有上传文件不会被删除；标记缺失后，必须先补充上传才能确认齐全、关闭风险。
- 资料可先补传并保持缺失状态，再经核查确认齐全；上传或台账保存失败会保留表单并提示，不会降级成只保留文件名。刷新后保留收货单、照片和资料分类。
- 每日例会中的今日计划只确认实际完成百分比，单项点击“确认并锁定”立即写回今日跟踪；确认后不能修改。保存明日计划不会自动确认今天的数据。
- 本轮定向验证：`node _test_material_closure.js`（隔离浏览器和随机本地端口，仅公开前端资源，不读取生产数据库或上传目录）。

## 例会锁定与待办定向验证

- 运行 `node _test_meeting_rules.js`：独立临时数据库、附件目录与浏览器验证实际/计划百分比、确认后锁定、刷新保留、直接请求防覆盖、日期隔离及五种岗位的待办范围；不读取生产数据。
- `meeting-rules.js` 是浏览器与服务端共享的规则文件，部署时须一起携带（云部署 Dockerfile 已包含）。
- 多人版使用专用确认接口和服务端不可修改校验；离线版仅能保证正常界面操作锁定，不能防止手动篡改浏览器本地数据。旧记录没有独立例会确认标记，保留原记录，但不擅自当成已确认数据，需要例会核实一次。

## 月、周、日进度关联

1. 上传月横道图后，在下方“月目标清单”登记单体、施工阶段、当前起点、目标及统计口径。例如3#楼从1层到5层，统一节点为“梁板浇筑完成”。
2. 从月目标点击“安排周目标”，自动继承月目标编号；填写本周日期、起点和目标，例如1层到2层。也可独立新建周目标，但必须明确选择所属月目标，不能只按名称或日期猜测。
3. 仅从侧栏“每日例会”编制日工作，逐项选择所属周目标，自动带出月目标、责任人和班组。临时工作可留为“计划外 / 待补关联”，不强行计入上级目标。
4. 工程量口径填写当天计划量；实际贡献=当天计划量×例会实际完成率。周10吨、日计划2吨、实际75%，贡献1.5吨，周完成15%。不能再次乘日计划目标百分比，也不能简单平均每日百分比。
5. 节点口径填写施工楼层；仅在该项完整完成确实代表统一节点达成时勾选“节点达成”。计划目标100%、例会实际100%且前序楼层连续确认后推进。钢筋绑扎完成不能当成梁板浇筑完成。1→5层目标确认2层后，月进度25%。
6. 不便计量的工作可使用明确权重：周目标0—100，指定对月目标的贡献份额；日工作再分解本周份额。份额需人工确定，不自动给不同工序相同权重。
7. 自动续排保留原工作范围编号并带入剩余量；汇总按原范围封顶避免重复计入。跨周/月需要人工重新选择有效周目标；跨月周可并列展示不同月目标，日执行只能落在相应月目标的日期内。
8. 改名或更换原文件不影响固定编号关联。已分解目标不能改动起止、范围和口径；已确认日计划不能改归属和计划量。需要调整时保留原记录、新建调整目标，避免改写历史。未确认旧计划须先人工明确关系，已锁定旧记录不追溯猜测关联。

目标统计位于月/周原文件下方及每日执行页的“日 → 周 → 月实际进度”。明确工程量、统一验收节点与权重的目标仍按上述口径统计；上传月计划自动识别见下一节。运行 `npm run test:schedule` 做相关定向测试，不运行全套回归。

## 月计划自动识别与自然周生成

- 多人服务器版上传月计划后自动打开识别核对窗口。已有月文件可从月计划页点击“识别已上传月计划”批量处理，或在单份文件旁点“识别月目标并生成周计划”。一份含1—12月分区的图片可以一次处理全年。
- 此版图片布局支持清晰PNG/JPG、按月分区、左侧编号及施工名称、横向日刻度、红/蓝施工横条；识别文字位置与横条，提取名称、起止日期、原文月完成节点。只识别支持的版式，不宣称任意横道图都准确。支持CSV/XLSX中带完整开始/结束日期的工作行；PDF/Word/MPP仍保留预览/原件，不自动解析其中的横道图。
- 核对窗口只需修正少量错字、日期或取消不可靠条目，一次确认即追加月安排和周安排。按自然周及自然月边界切分；不均分工程量，不把7个作业日当成工程完成百分比。未注明工程量/验收节点的目标为“施工安排”口径，显示日期、作业天数和原文节点，不编造累计实际完成率。日工作可在每日例会选择这些周安排；每日实际确认及锁定规则不变。
- 同一文件内容重复上传/识别使用内容摘要、月份、工作编号去重，保留已核对的名称；原文件不修改、不删除。更换月文件时保留原附件引用于fileHistory；生成记录保留sourcePlanId/sourceFileKey及横条证据。历史附件引用仍保留，目前没有独立文件版本选择界面。不同版本文件不会自动覆盖已拆分或已确认的旧目标，请勿把版本更新当作重复识别。
- `file://`离线页面没有服务端OCR，图片识别会明确提示改用服务器网址，不清空数据、不静默失败；CSV/XLSX可在浏览器解析。file://本机存储与HTTP项目数据库彼此独立，当前离线已上传的文件不会自动迁入服务器项目，应先保留离线数据及原件，再向目标服务器项目上传原文件；本轮没有迁移或覆盖旧数据。
- Windows服务器需安装简体中文OCR语言组件，识别在服务器本机通过Windows OCR完成；Linux服务器需安装Tesseract及chi_sim、eng语言数据。部署Dockerfile已增加这些包（[Alpine包说明](https://pkgs.alpinelinux.org/package/edge/community/x86_64/tesseract-ocr)）；Linux容器尚未在本轮实际构建/验证。没有接入付费云OCR，也不向第三方发送计划文件。
- 定向测试：`node _test_schedule_recognition.js`（样图本机OCR与日期分周规则）、`node _test_schedule_recognition_flow.js`（独立临时服务器、数据库、上传目录及浏览器，真实上传/识别/核对/生成/去重及完成锁定）。样图默认路径为 `E:/新会话解决问题/月进度计划横道图.png`，可通过 `ZHUXU_TEST_CHART` 指定相同版式样图。测试不读取生产数据库、不操作用户浏览器存储或真实上传目录。
